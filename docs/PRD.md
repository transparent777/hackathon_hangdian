## 二、产品概述

### 2.1 产品名称

**赛博陪伴相机**

### 2.2 一句话定义

每天随机 Roll 一只热门虚拟生物，溶进你的真实生活照片，生成「赛博陪伴」瞬间。

### 2.3 产品愿景

在独居与碎片化生活中，用熟悉的 meme 角色和真实场景的照片，为用户提供**轻量、可分享、可回看**的情感陪伴体验——不需要账号、不需要养成、不需要付费。

### 2.4 创作灵感

- **痛点**：年轻人想要「被陪伴」，但电子宠物、社交 App 往往门槛高、耗时长
- **机会**：奶蛙、doro、耄耋等梗角色在年轻群体中有强烈认同感
- **解法**：AI 溶图把虚拟角色「放进」用户真实生活照，一张照片 + 一句陪伴语 = 即时情绪价值
- **延伸**：陪伴日记将单次溶图沉淀为可回看的手账时间线，形成长期情感记忆

## 三、目标用户

### 3.1 核心用户画像

| 维度 | 描述 |
|------|------|
| 年龄 | 18–28 岁 |
| 平台 | 微信高频用户 |
| 文化 | 熟悉奶蛙 / doro / 耄耋等网络梗 |
| 场景 | 独居、学习、办公、居家等日常碎片时刻 |
| 需求 | 轻量陪伴感、情绪慰藉、可分享的有趣内容 |
| 排斥 | 重度养成、强制登录、复杂社交、付费门槛 |

### 3.2 典型使用场景

1. **早晨起床**：Roll 到 doro，拍窗台阳光，生成「doro 趴在窗边」+ 软糯陪伴语
2. **深夜加班**：Roll 到耄耋，拍书桌键盘，生成「耄耋趴在键盘旁」+ 嘴硬心软批注
3. **周末摆烂**：Roll 到奶蛙，拍沙发，生成荒诞摆烂风格溶图，转发好友吐槽
4. **回顾**：在历史 / 陪伴日记中翻看过去一周的「赛博陪伴」记录

## 四、解决方案与核心创新

### 4.1 解决方案

```
用户痛点                    产品方案
──────────────────────────────────────────────────
想要陪伴，怕太重        →   无账号、无养成，打开即用
角色要有认同感          →   三大热门 meme IP
需要情绪价值            →   溶图 + 陪伴语 + AI 日记批注
要能分享                →   拍立得结果页，一键存相册/转发
```

**产品闭环**：Roll（抽卡感）→ 溶图（视觉陪伴）→ 陪伴语（即时情绪）→ 陪伴日记（长期记忆）→ 历史回看（情感沉淀）

### 4.2 核心创新

| 类型 | 创新点 |
|------|--------|
| **产品创新** | 「赛博陪伴」范式：把 meme 角色溶进真实场景，而非聊天或养成 |
| **产品创新** | 每日 Roll + 三档稀有度，轻量抽卡机制 |
| **产品创新** | 陪伴日记：溶图 + 手账式 AI 批注，三角色 × 三稀有度差异化 |
| **技术创新** | 多策略溶图管线（seedream-full / hybrid / asset-composite）可热切换 |
| **技术创新** | Hybrid 模式：Seedream 生成 + U2Net-P 分割 + 像素级背景保真 |
| **技术创新** | 场景导演：DeepSeek 多模态分析选动作、锚点、比例 |
| **体验创新** | 拍立得 + 手账手绘 UI，情绪表达优先于工具感 |

## 五、功能需求

### 5.1 MVP 功能（必须完成）

| ID | 功能 | 描述 | 优先级 | 状态 |
|----|------|------|--------|------|
| F01 | 每日抽取 | 随机 Roll 一只陪伴兽（奶蛙 / doro / 耄耋），含普通/稀有/传说稀有度 | P0 | ✅ |
| F02 | 拍照选图 | 支持相机拍照或相册选图，单张上传 | P0 | ✅ |
| F03 | AI 溶图 | 上传原图 + 角色信息，返回角色融入场景的结果图 | P0 | ✅ |
| F04 | 结果展示 | 拍立得风格展示结果图 + 角色名 + 陪伴语 | P0 | ✅ |
| F05 | 保存分享 | 保存到相册、转发微信好友 | P0 | ✅ |
| F06 | 历史记录 | 本地保存最近 10 条溶图，支持点击回看 | P0 | ✅ |
| F07 | 降级提示 | AI 失败或降级时，向用户明确标注状态 | P0 | ✅ |

### 5.2 加分功能

| ID | 功能 | 描述 | 优先级 | 状态 |
|----|------|------|--------|------|
| F08 | 陪伴日记 | 手账式时间线，展示历史溶图 + AI 批注，按角色字体与稀有度差异化 | P1 | ✅ |
| F09 | Roll 稀有度动画 | 抽取时的转盘/老虎机动效 | P2 | ❌ |
| F10 | Loading 文案轮播 | 溶图等待时趣味文案轮播 | P2 | 部分完成 |

### 5.3 明确不做（Out of Scope）

- 账号体系 / 用户登录
- 付费、商城、虚拟货币
- 复杂养成、等级、任务系统
- 实时 AR 相机
- 第四个 IP 角色
- Figma 设计稿（直接写页面）

## 六、用户流程

### 6.1 主流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 冷启动    │ →  │ 首页 Roll │ →  │ 拍照选图  │ →  │ AI 溶图   │ →  │ 结果展示  │
│ 开场动画  │    │ 今日陪伴兽 │    │ 预览贴纸  │    │ Loading  │    │ 保存分享  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 6.2 次要流程

- **历史回看**：历史 Tab → 点击条目 → 结果页（只读模式）
- **陪伴日记**：我的 Tab → 陪伴日记 → 手账时间线浏览
- **再拍一张**：结果页 → 携带原图路径返回拍照页

### 6.3 答辩黄金 Demo 脚本

1. 打开小程序，跳过/看完开场动画
2. 首页点击「抽取今日陪伴兽」，Roll 到「耄耋」
3. 进入拍照页，拍摄书桌/键盘场景
4. 点击溶图，等待约 10 秒
5. 结果页展示「耄耋趴在键盘旁」+ 陪伴语
6. 保存到相册 / 转发好友

## 九、AI 能力需求

### 9.1 溶图

| 项 | 要求 |
|----|------|
| 输入 | 用户原图 + characterId + rarity |
| 输出 | 角色融入场景的结果图 URL |
| 画风 | 保持平面梗图风格，禁止写实/3D 变形 |
| 背景 | hybrid 模式下背景像素级不变 |
| 策略 | seedream-full / hybrid / asset-composite 可配置 |
| 超时 | 整路由预算 120s，前端上传超时 180s |
| 降级 | 候选保留 → 透明贴纸 → 明确标注 degraded 状态 |

### 9.2 陪伴语

| 项 | 要求 |
|----|------|
| 来源 | `ai/quotes.json` 随机抽取 |
| 长度 | 短句，适合结果页展示 |
| 时机 | Roll 时预览 + 溶图结果一并返回 |

### 9.3 陪伴日记批注

| 项 | 要求 |
|----|------|
| 输入 | 用户原图（溶图前场景）+ characterId + rarity |
| 输出 | `diaryNote`（第一人称手账批注）+ `fontStyle` |
| 模型 | DeepSeek Flash 多模态 |
| 约束 | 看图说话、禁元信息、禁词过滤、按稀有度控制字数 |
| 降级 | 预设 fallback 文案池 |

### 9.4 效果验收标准

- 溶图人工评判：≥ 7/10 张合格（角色可辨识、场景融合自然）
- 日记批注：符合角色人设、无禁词、长度合规
- 降级路径：任何 AI 失败不阻断主流程，用户可见降级说明

## 十四、风险与预案

| 风险 | 预案 |
|------|------|
| AI 溶图太慢 | 降分辨率、异步轮询、前端 Loading 趣味文案 |
| 角色崩图 | 多层降级：AI 候选 → 透明贴纸 → 明确标注 |
| API 现场崩溃 | 备用标杆样图 + 30s 录屏 Demo |
| API 费用超支 | 每日限流 5–10 次 |
| 微信审核来不及 | 体验版 + 录屏备用 |
| 包体积超限 | 压缩 intro.mp4、忽略 node_modules |
